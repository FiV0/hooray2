Conjunctive queries fit. Every clause must hold, so each one can extend or reject a row at the variables it mentions.

Worst-case optimal joins in Hooray · 11

Before the implementation, the goal. The holy grail is a single worst-case optimal join over the whole query, not a few worst-case optimal joins glued together. That means the trie construction from the last slides for every clause at once: one variable order, and at each variable every clause that mentions it takes part. Patterns propose candidates, predicates filter them, functions compute them. In the example, the order is country, city, population, district. The first pattern proposes Germany and USA, then their cities. Once a city's population is bound, the predicate rejects Munich, so its districts are never looked at, and the last pattern proposes the districts of Berlin, NYC and LA. Every clause takes part in the one join, and the result is the trie from before minus Munich. For conjunctive queries, where every clause must hold, this works directly: a clause can extend or reject a row at any of its variables. Disjunction is the problem. An or only holds if one branch accepts the complete row, but once its branches are spread over the levels of the variable order, nothing remembers which branch admitted which value. We will see exactly that bug in a moment. So for now we focus on conjunctive queries.
