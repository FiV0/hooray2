{:find [?name ?age]
 :where [[?e :age ?age]
         (or (and [?e :name "A"]
                  [(< ?age 30)])
             (and [?e :name "B"]
                  [(< ?age 40)]))
         [?e :name ?name]]}
;; => [["B" 35]]

1

The triples bind ?e and ?age. The or cannot propose: no branch can ground ?age.

2

Once ?e and ?age are bound, each branch runs as its own plan over those rows.

3

Branch results are unioned and matched back. Branch A keeps nothing, branch B keeps ("b", 35).

How the or query from before runs now. The or cannot introduce age, because branch two only has a predicate on it, so the triples bind e and age first. Once both are bound, the or validates as a unit: each branch is a complete nested plan that receives the bound rows as an input relation.
